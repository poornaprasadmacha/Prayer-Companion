1. PROJECT OVERVIEW & MULTI-TIER ARCHITECTURE
================================================================================
Prayer Companion is a Christian prayer and thanksgiving application featuring:
1. Personal Prayer & Thanksgiving: Fast, local-first personal prayer journal,
   daily prayer tracking ("I Prayed Today"), answered prayer testimonies, and
   daily gratitude entries.
2. Prayer Companions (Pray Together): Voluntary community prayer sharing where
   members can ask companions to pray for their needs, commit to pray ("I'll Pray"),
   and send respectful words of encouragement.
3. Administrator Dashboard: Secure management interface restricted via server-side
   allowlist to `poornaprasad12344@gmail.com` with real-time aggregate statistics,
   user management (CSV export), delivery monitoring, community moderation, and
   audit logs.
4. Local-First Instant Loading: Cached in IndexedDB (`PrayerCompanionDB`). Renders
   the personal dashboard in < 50ms without waiting for network connectivity.
5. Background Non-Blocking Synchronisation: Asynchronous queue pushes local changes
   to Google Sheets and pulls incremental updates using Last-Write-Wins conflict
   resolution.
6. Offline Durability: Full PWA support with Cache-First app shell caching.

3. TECHNOLOGY STACK & DESIGN DECISIONS
================================================================================

  for instant loading, high security, and minimal memory footprint.
- IndexedDB (PrayerCompanionDB): Primary local database for storing user records

6. COMPLETE GOOGLE APPS SCRIPT REFERENCE (apps-script/Code.gs)
================================================================================
The complete, production-ready code is located at `apps-script/Code.gs` in your
project folder.

Core functions implemented in `Code.gs`:
- `setupDatabase()`: Auto-creates all 16 sheets with bold, styled, frozen headers.
- `seedDailyContent()`: Populates 31 curated verses and quotes into Daily_Content.
- `doGet(e)` / `doPost(e)`: Main HTTP dispatchers with CORS JSON output.
- `isAdmin(email)`: Server-side allowlist check (verifies against poornaprasad12344@gmail.com).
- `handleRequestOtp(payload)`: Generates 6-digit OTP, salts/hashes with SHA-256,
  enforces 60s cooldown rate limit, and dispatches email.
- `handleVerifyOtp(payload)`: Validates hash, verifies expiration (<5 min) and max
  attempts (5), invalidates OTP, creates user, issues 30-day session token.
- `validateSession(rawToken)`: Validates SHA-256 session token hash and strictly
  derives authenticated user identity on the server.
- `handleAdminAction(action, authAdmin, payload)`: Protected router for all admin operations:
  * `admin_get_overview`: Server-side aggregation of system statistics.
  * `admin_get_users`: Paginated, searchable user directory.
  * `admin_get_prayer_stats`: Daily, weekly, monthly time-series trends and categories.
  * `admin_get_prayer_points`: Privacy-conscious viewer with audit logging.
  * `admin_get_email_logs`: Delivery monitoring logs.
  * `admin_get_moderation_reports`: Community reports review.
  * `admin_moderate_content`: Content hide/restore actions.
  * `admin_send_test_email`: Controlled test email to admin's inbox.
- Community Handlers:
  * `handleCommunityShareRequest`: Voluntary prayer sharing.
  * `handleCommunityGetRequests`: Public community request listing with supporter counts.
  * `handleCommunityToggleCommitment`: "I'll Pray" commitment & undo without altering personal history.
  * `handleCommunitySendEncouragement`: Length-validated encouragement message submission.
  * `handleCommunityReportContent`: Reporting inappropriate content.
- `checkAndSendScheduledEmails()`: Multi-timezone scheduler that checks user
  local times, verifies `Email_Log` for duplicate prevention, and delivers morning
  (3:00 AM) and evening (6:00 PM) emails.

12. EMAIL OTP AUTHENTICATION SETUP & SECURITY TRADE-OFFS
================================================================================
1. User enters email -> server generates 6-digit random code.
2. Code is salted and hashed with SHA-256 before storage in `OTP_Requests`.
3. Sent via GmailApp in clean HTML format.
4. Server enforces 60-second cooldown per email and 5-minute expiration.
5. Upon verification, OTP is marked used and invalidated.
6. A cryptographically random 48-character session token is created, hashed with SHA-256,
   stored in `Sessions`, and returned to the client.
7. If the authenticated email matches `poornaprasad12344@gmail.com`, the session
   response includes `is_admin: true`, unlocking the Admin Dashboard.

22. COMMON ERRORS & TROUBLESHOOTING GUIDE
================================================================================
1. Error: "Access Denied: You do not have administrator permissions"
   Reason: Logged-in email does not match `poornaprasad12344@gmail.com`.
   Solution: Sign in using `poornaprasad12344@gmail.com`.

2. Error: "Google Apps Script Web App URL is not configured yet"
   Solution: Paste your deployed URL in Settings and click "Save Preferences".

3. Error: "Verification code expired"
   Solution: Request a new code. Codes expire in 5 minutes.

4. Error: CORS or Network Error calling Apps Script
   Solution: Ensure Web App deployment access is set to "Anyone" and URL ends with `/exec`.

5. Error: "Failed to send invitation email: You do not have permission to call MailApp.sendEmail"
   Solution: Google Apps Script requires a one-time authorization grant from the script owner to send emails:
   a. Open your Google Apps Script project in the editor (script.google.com).
   b. Ensure `appsscript.json` includes `oauthScopes` for `script.send_mail` and `gmail.send`.
   c. In the function dropdown on the toolbar, select `setupDatabase` and click "Run".
   d. Google will display "Authorization required". Click "Review permissions".
   e. Choose your Google account -> Click "Advanced" -> Click "Go to Prayer Companion (unsafe)" -> Click "Allow".
   f. The frontend also includes an instant one-click fallback: `[ Open in Email App (mailto:) ]` pre-populated with recipient and text.
